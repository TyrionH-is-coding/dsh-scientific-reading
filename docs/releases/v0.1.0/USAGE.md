# 使用与数据维护

适用于完成[安装](INSTALL.md)后的原生插件 A。以下对话在 DSH 的 **文献模式**中进行。当前为 0.1.0-rc.1，实际覆盖边界以交付目录的 `ACCEPTANCE.md` 为准。

## 五个起步任务

### 1. 录入一篇文献

把 DOI、文章链接或题名粘贴到对话中，接着发送：

> 把这篇文献加入文献库。先查重，补全能核实的题录和摘要；缺失信息保留待补状态。

预期先看到本地条目，题录补全、摘要翻译和 Excel 更新可能继续在后台执行。没有查到摘要时显示待补，不应出现根据题名编写的“摘要”。题名有歧义时选择正确条目。

### 2. 归类并阅读摘要

> 建立“入门测试”文件夹，把刚才的文献放进去，再打开它的双语摘要。

文献列表用于搜索、筛选、分类和打开资产。文件夹是单归属，标签可多个。全文未就绪时仍可以阅读已有摘要。

### 3. 获取或补入 PDF

> 为这篇文献查找 OA 正文 PDF；如果没有可用文件，告诉我需要补入 PDF。

原生插件自动获取 OA；需要机构认证的全文，由用户在自己的渠道取得后补入。将文件放在本机稳定位置，向 Agent 提供其完整路径并说明对应哪篇文献：

> 将我提供的本地 PDF 挂接到刚才这篇文献，校验它确实是 PDF，并核对题名是否对应。

浏览器可打开一个网页不等于取得 PDF。题录与 PDF 对应关系不明确时，先核对，避免把不同文章挂在同一条目下。

### 4. 开始精读和导出图表

> 对这篇已补入 PDF 的文献开始全文精读，沿用已经完成的步骤，并告诉我当前进度。

任务依次处理 PDF 校验、MinerU 解析、翻译与审核、Reader 和派生资产。需要补文件或人工选择时按状态提示处理；等待 Agent 处理翻译时继续该会话。任务中断后查询并继续原任务，不必另建同一篇文献。

Reader 就绪后核对正文、图表、公式和参考文献，再记录自己的理解。需要图表时：

> 整理这篇文章的正文图表，保留原图编号与图注，并告诉我导出位置。

导出范围来自解析结果；没有可靠表格结构时不会凭空生成单元格。翻译与解读仍需对照原文，定位吻合也不等于科学结论已验证。

### 5. 在 Excel 记录笔记

默认总表是 `<数据目录>\library\scientific-reading.xlsx`。首版使用固定列，不自定义表头、列名或系统标识。

在允许回写的 **个人思考、个人理解程度、用户笔记**中编辑并保存，然后在文献对话中发送：

> 把 Excel 中允许回写的用户字段同步到文献库，再刷新总表；如果有身份冲突，先保留原文件并告诉我原因。

Excel 是派生视图，系统题录不通过任意单元格编辑覆盖主库。文件被 Excel 占用时先保存并关闭，再重试刷新；无需重新录入文献。同步后的笔记应读回确认。

## 升级前备份

升级前先保存并关闭 Excel，在对话中要求创建整库备份。指定一个**库外、尚未使用的绝对文件路径**，例如自己备份目录中的新 `.zip` 文件。不要把备份放进被备份的数据目录。

> 将当前文献库备份到我指定的新文件，等待活动写入完成，并核对归档完整性。完成后返回备份路径与校验结果。

归档保留主库、阅读资产和用户记录；运行环境及凭据不在产品备份中。最好在升级前把归档恢复到一个新目录并抽查条目、PDF、Reader 和笔记。恢复入口不会自动切换当前库或继续未完成任务。

如果当前旧版本没有整库备份入口，先正常退出该库的所有 DSH/worker 并关闭 Excel，再完整复制旧数据目录到另一个位置；不要只复制正在使用的 SQLite 主文件。保留原目录和原安装包，待新版本验证后再处理。

## 升级、恢复与回退

- **升级插件**：完成备份，正常停止对应 DSH，核对新 Release 的 `.tgz` 校验和，重复安装命令，再启动同一环境。首次打开先检查几篇旧文献和笔记。
- **恢复备份**：选择不存在或空的新目录；已有数据的目录不会被覆盖。恢复成功后核对资产，再由用户决定是否把插件的数据位置切到恢复目录。MinerU Key 和模型设置分别重新配置。
- **回退程序**：停止对应 DSH，重新安装上一个已保留的 `.tgz`。程序回退不能撤销数据库格式变化；如果旧程序不支持当前数据库，应使用升级前备份恢复到新目录，而不是让旧程序直接写入新库。
- **继续任务**：恢复后的未完成任务需明确继续，不会使用历史 PID 自动启动。任务状态指出缺少文件或凭据时先补齐。

Excel 不是整库备份，单个 Reader HTML 也不包含完整的库关系、来源记录和任务状态。

## 卸载

先正常停止安装该插件的 DSH，再执行：

```powershell
dsh plugin --profile web remove @dsh-external/dsh-scientific-reading
if ($LASTEXITCODE -ne 0) { throw '插件卸载失败，请保留错误信息。' }
```

如果使用自定义 DSH 环境，沿用安装时相同的 `DSH_HOME` 和 Profile。卸载不会主动删除文献数据；预设也可能保留。需要清理时先在 DSH 中确认预设及数据目录的实际归属，再单独处理，避免删除其他实例的内容。
