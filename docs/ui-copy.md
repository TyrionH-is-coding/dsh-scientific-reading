# 界面文案规范

适用于文献库、阅读页、设置、弹窗、连接页、通知与错误提示。后续前端修改遵循同一标准。

布局、主题与侧栏交互同时遵循[界面设计依据](ui-design.md)。

每段文字都应帮助用户理解当前内容、作出选择或完成操作。不能回答其中任何一项的文字删除；可由标题、控件或状态直接表达的信息不再重复说明。

- 按钮写操作，如“保存”“预览”“打开阅读页”。一条提示尽量只说一个结果或下一步。
- 使用用户语言：文献信息、文献对话、阅读外观、添加 PDF。内部字段、provider 标识、任务编号、修订号、JSON 和调试信息留在接口与工程记录。
- 模型选项只取实际连接返回的列表；未连接时不以默认偏好补造模型选项。主题用成套预设预览，不暴露取色器或内部色值。
- 默认只显示模型名。同名模型确需区分时显示用户可识别的连接名称，实际模型与连接绑定不能改变。
- 文件夹用名称选择，用户不应输入内部 ID。文件位置、DOI 和页码在帮助打开文件或核对来源时保留。
- 不展示尚未实现的按钮或开发计划。测试资料必须在验收记录中明确标注，不能暗示真实模型调用已验证。
- 保存与连接成功、部分失败与全部完成必须准确区分。错误说明发生了什么及如何继续，不直接展示异常栈或内部错误码。
- 保留会改变用户决定的信息，如对话不持久保存、摘要初筛、AI 内容待核对、来源变化、账号额度共享和必要确认。
- 论文正文、译文、图注、作者论述和用户笔记不属于界面文案，不因精简界面而删改。

验收查看实际桌面与窄屏界面，覆盖正常、空白、加载、未连接、失败和保存后的状态，同时确认显示文案改变不影响真实操作。
