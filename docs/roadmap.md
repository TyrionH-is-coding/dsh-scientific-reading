# DSH Scientific Reading 发布路线

## V1：个人文献库主链路

V1 只交付一条稳定、可恢复、适合长期使用的主链路：

```text
对话快速入库
  -> SQLite 建档与去重
  -> Abstract 中英对照
  -> 单篇或批量取得 PDF
  -> MinerU、翻译与精读 HTML
  -> 文献页导航与归类
  -> 美观 Excel 总表与白名单用户字段回写
```

### V1 必须完成

1. 文献页职责收敛为资料库导航，只保留归类和缺失 PDF 的单篇/批量补下载。
2. 文献页改为两行式紧凑列表，只突出作者、年份、期刊、标签、PDF、HTML 和 Excel 定位。
3. 新增首次安装只展示一次的【设置与状态】页，所有真实环境验证由用户点击触发。
4. 支持经过验证的本机 MinerU 和 MinerU API，使用统一 provider、规范化和资产发布合同。
5. MinerU API Key 使用 Windows DPAPI 安全保存，并保留环境变量回退。
6. 下载按 OA/HTTP、系统 Chrome、可选 CloakBrowser 增强包、手动 PDF 的整批降级流程执行。
7. PDF、精读 HTML、Figure/Table 导出和 generation manifest 长期稳定保存。
8. Excel 固定格式、稳定身份、刷新 pending 和白名单回写通过真实 Excel 占用/修改场景验收。
9. 删除飞书产品入口、运行工具、配置和测试依赖；历史资料只留在归档，不污染当前说明。
10. 使用虚构工科文献完成真实 Bundle、HTTP、浏览器、批量下载、双 MinerU provider、reader 和 Excel 回写验收。

### V1 明确不做

- 文献推荐、文献推送、引用网络和知识图谱。
- 逐篇 JSON 证据卡、自动综述或跨论文证据综合。
- SQLite 与 Excel 任意字段双向同步。
- AI 自动挑选关键图、批量删除或多个 MinerU/全文翻译任务并行。

## V2：上游发现与下游证据卡

V2 由两个可独立实现和验收的子项目组成。

### V2A：文献发现与推荐

```text
研究问题 / 关键词 / 种子论文
  -> 多来源检索和身份规范化
  -> 去重、相关性解释和排序建议
  -> 候选文献列表
  -> 用户确认入库
  -> V1 下载与精读链路
```

- AI 负责查询扩展、相关性解释和排序建议，不直接决定入库。
- 每条候选记录保留稳定标识、发现来源、查询词和推荐理由。
- 推荐不得自动触发付费、机构认证或 PDF 下载。

### V2B：逐篇 JSON 证据卡

- 每篇文章生成一个有明确 schema 版本的 `.json` 文件。
- 卡片记录研究问题、设计、样本、方法、主要结果、局限性、可支持与不可支持的结论，以及对应原文位置。
- 事实、作者解释和系统推断必须分字段保存，不能混写。
- 证据卡由已验证的 PDF/解析来源生成，并记录源文件 SHA 和生成版本。
- 综述写作、证据比较和其他下游任务只消费证据卡，不反向修改原始论文资产。

V2A 与 V2B 不进入 V1 的工期和发布门禁；V1 稳定后分别立项。
