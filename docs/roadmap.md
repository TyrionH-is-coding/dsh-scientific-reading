# DSH Scientific Reading 发布路线

## 0.1（V1）：个人文献库主链路

2026-09-05 版本决定：首版从简，使用固定 Excel 格式和默认 Reader；自定义展示、模板和文献雷达进入 0.2 待办，不阻塞 0.1。2026-09-07 补充：Figure 关联解读与 DSH Chat 讨论也列入 0.2。两项目边界见[双项目工程规划](superpowers/specs/2026-09-05-two-product-literature-architecture.md)。本文跟踪原生插件 A，Codex 工作台 B 独立发布。

0.1 只交付一条稳定、可恢复、适合长期使用的主链路：

```text
对话快速入库
  -> SQLite 建档与去重
  -> Abstract 中英对照
  -> 自动获取 OA PDF / 补入本地 PDF
  -> MinerU、翻译与精读 HTML
  -> 文献页导航与归类
  -> 美观 Excel 总表与白名单用户字段回写
```

### 0.1 当前收口与验收门槛

以下列出首版目标和验收门槛，包含已整合能力及按新方向仍需收口的部分；不能据此声称已完成 OA 边界和设置精简。现有结果见[内容保真与发布验收](superpowers/executions/2026-09-05-content-fidelity-release.md)，后续改动应补充对应验收证据。

1. 文献页职责收敛为资料库导航，只保留归类和缺失 PDF 的单篇/批量补下载。
2. 文献页改为两行式紧凑列表，只突出作者、年份、期刊、标签、PDF、HTML 和 Excel 定位。
3. 沿用并精简【设置与状态】入口，保留 MinerU Key、资产位置和必要状态；不为未来自定义重做布局或增加模板、字段配置入口。
4. 支持经过验证的本机 MinerU 和 MinerU API，使用统一 provider、规范化和资产发布合同。
5. MinerU API Key 使用 Windows DPAPI 安全保存，并保留环境变量回退。
6. 原生插件只自动获取有开放来源依据的 OA PDF，失败后等待补入本地 PDF；退出高校认证、Chrome 和 CloakBrowser 的自动下载接力。授权获取由项目 B 的 Codex 侧承担，不作为 A 的下载能力或发布门槛。
7. PDF、精读 HTML、Figure/Table 导出和 generation manifest 长期稳定保存。
8. Excel 固定格式、稳定身份、刷新 pending 和白名单回写通过真实 Excel 占用/修改场景验收。
9. 保持飞书退出当前运行面；历史资料只留在归档，遗留字段不作为产品能力。
10. 使用合成及非敏感样本完成实际 Bundle、HTTP、浏览器界面、OA/本地 PDF、支持的 MinerU provider、Reader 和 Excel 回写验收；代码整合本身不替代这些宿主门禁。

发布前优先解决影响正文、图表、引用完整性和笔记保留的问题；已有验收记录中未关闭的 R1 及真实服务、Excel 回写覆盖不因版本从简而自动通过。新增自定义功能不进入首版修复范围。

### 0.1 明确不做

- 文献推荐、文献推送、引用网络和知识图谱。
- 逐篇 JSON 证据卡、自动综述或跨论文证据综合。
- SQLite 与 Excel 任意字段双向同步。
- AI 自动挑选关键图、批量删除或多个 MinerU/全文翻译任务并行。
- Excel 字段显隐、重排、显示名或格式方案，自定义研究字段，以及 HTML 模板导入、编辑、预览和分类方案。

## 0.2：用户自定义、Figure 关联解读与文献雷达（待做）

完整设计方向保留在[双项目工程规划 §7.1](superpowers/specs/2026-09-05-two-product-literature-architecture.md)，状态为待做，0.1 发布后再细化实施顺序。原生插件提供共享能力，Codex 工作台复用。

### Figure 关联解读与 DSH Chat 讨论

2026-09-07 用户新增需求：用户选中论文中的某个 Figure 后，系统自动识别该论文中与这张图相关的内容，用户随后可在 DSH Chat 中与 LLM 持续讨论、解释该图。状态为 0.2 待做。

```text
在 Reader 中选中 Figure
  -> 识别图注、正文引用和相关段落
  -> 将所选图片及带来源的上下文带入当前 DSH Chat
  -> 用户提问，LLM 结合图与原文解释，支持继续追问和跳回原文
```

- 复用 MinerU 保存的图片、图注和页码，以文献 ID、资产 ID 和源 PDF SHA 绑定上下文；识别正文中的 Figure/Fig. 编号与子图引用，并关联结果、方法和讨论中相关的段落。
- 在 Chat 中明确展示当前讨论的 Figure 及关联内容，保留原文段落定位。连续追问沿用所选图的上下文；切换 Figure 时明确更新，避免混入另一图或另一篇论文的内容。
- LLM 的解释区分图中可见信息、作者原文结论与推断，引用可跳回相应图注或正文。未向模型提供图像时明确仅依据图注和正文；关联内容不足或编号有歧义时保留不确定性。
- 验收覆盖同篇多图、子图引用、跨页引用及缺少明确正文引用的样本；确认选图后上下文关联正确、可在真实 DSH Chat 中连续讨论、来源可定位，且不混淆图或文献身份。

### 文献雷达

2026-09-05 用户新增方向：Agent 帮助用户梳理、确认研究方向，并寻找方向相关的优质文献。既有“文献发现与推荐”规划合并到本项，正式进入 0.2 待办。

现有项目与 Skill 的[复用调研](../outputs/literature-radar-research-2026-09-05/调研报告.md)已完成：锁定 12 个仓库，重点检查 PaperRadar、医学雷达和方向/证据判断 Skill，并做有限纯函数与公开接口探针。建议组合复用检索与工作流，候选账本、身份合并和纳入流程沿用本项目；来源、许可、适配代价及尚未验证的部分见报告。本轮不安装候选项目或实现雷达，0.1 发布范围保持不变。

```text
用户目标 / 已有文献 / 种子论文
  -> Agent 提出并解释方向与子方向
  -> 用户确认或修正，保存可修改的方向配置
  -> 多来源检索和身份规范化
  -> 与文献库和历史候选去重
  -> 相关性、研究质量与阅读价值说明
  -> 候选列表，支持用户筛选反馈
  -> 用户选择纳入，衔接既有 PDF 与精读链路
```

- 方向配置包括研究问题、关键词与同义词、纳入与排除范围、种子论文及关注的研究类型。已有明确方向时直接整理成配置；方向不明确时提供有文献依据的建议，不每轮重新要求用户确认同一方向。
- “优质”分别说明主题相关性、研究设计与证据、对当前问题的价值以及时效性；经典研究与新进展均可进入候选，不只按期刊影响因子、引用数或发表日期排序。相关的阴性或相反结论也应进入筛选范围。
- 仅取得摘要时，只作摘要层面的初筛；不能显示为已完成全文质量评价。预印本、撤稿或更正信息在可核实时标注，缺失信息保留不确定性。
- 每条候选保留稳定标识、发现来源、检索时间、查询词、推荐理由、判断依据和全文可获取状态。可发现非 OA 文献；A 仍仅自动获取 OA 或接收本地文件，B 的授权获取沿用既定分工。
- 支持按需扫描，并规划按用户设定频率进行增量扫描；去重后只提示新且相关的候选，保留“不相关”等反馈以改进后续筛选。周期扫描属于未来产品能力，本次不创建任何实际定时任务。
- 候选列表与已纳入文献分开；发现和推荐不自动启动正文下载或解析，用户选择纳入后复用既有流程。
- 雷达检索、候选与方向配置由 A 提供共享能力；A 由 DSH 对话操作，B 由 Codex 总管理员统筹方向与纳入，纳入后衔接本篇文献 chat。两项目沿用同一数据合同。

0.2 实施前验证方向配置可复用、候选去重和来源可追溯，并用相关、无关、相反结论及重复条目样本检查推荐说明。检索接口返回成功不等于推荐质量通过。

## 后续候选：逐篇 JSON 证据卡

这项保留既有规划，尚未排入 0.2；与文献雷达的简要候选说明分开评估。

- 每篇文章生成一个有明确 schema 版本的 `.json` 文件。
- 卡片记录研究问题、设计、样本、方法、主要结果、局限性、可支持与不可支持的结论，以及对应原文位置。
- 事实、作者解释和系统推断必须分字段保存，不能混写。
- 证据卡由已验证的 PDF/解析来源生成，并记录源文件 SHA 和生成版本。
- 综述写作、证据比较和其他下游任务只消费证据卡，不反向修改原始论文资产。

0.2 自定义、Figure 关联解读、文献雷达及后续证据卡均不进入 0.1 的工期和发布门槛；首版发布后再按版本范围细化实施。
