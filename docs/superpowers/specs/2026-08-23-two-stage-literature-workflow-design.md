# DSH Scientific Reading 两段式文献工作流设计

## 决策摘要

项目收缩为两个用户可理解的动作：

1. **入库**：数秒内把文献写入本地 SQLite 并显示在【文献】页；后台补齐题录、英文
   Abstract、中文对照、XLSX 快照和飞书记录。
2. **精读**：按需在后台串联合法 PDF 获取、校验、MinerU 解析、全文翻译和离线 HTML
   生成；失败时才展示机构浏览器或本地 PDF 等高级处理入口。

【文献】页从处理控制台改为导航主页。用户在这里归类文献，并快捷打开 Abstract 浅读、
PDF 原件、精读 HTML、飞书记录和本地资产目录。Zotero 不再属于产品边界。

## 产品目标

- 常规单篇入库在本地记录创建后立即返回，目标是 3–5 秒内出现在文献列表；Abstract
  翻译、XLSX 和飞书网络请求不得阻塞这一完成点。
- 用户只需要理解“入库”和“精读”，不需要理解下载器、MinerU、agent gate 或渲染阶段。
- SQLite 是唯一主库；PDF、精读 HTML 和解析资产具有稳定路径、哈希与来源记录。
- 轻量工作由脚本和后台 worker 完成；只有翻译、重点识别、结构化阅读字段和语义归类
  调用 AI。
- 单篇失败不影响批量中的其他文献；DSH 关闭或重启后任务可以从已完成阶段继续。
- 飞书用于在线检索和个人记录，XLSX 用于本地便携快照；二者都不是事实来源。

## 明确舍弃的范围

- 删除 Zotero 查重、写入、附件和迁移的运行链路，不再把 Zotero 作为默认或备用主库。
- 新流程不再生成九节式浅读、长篇浅读报告或 AI 选择的“关键图”。
- 主界面不再常驻“下载 PDF”“解析”“生成浅读”等底层阶段按钮。
- 不实现 SQLite、XLSX、飞书三方双向同步；XLSX 不接受回写。
- 不保留每篇文献飞书预览与逐次确认。有效环境变量和表格配置本身构成自动同步的启用条件。
- 不保留常驻三栏详情，不在 DSH 页面内嵌整篇精读 HTML。
- 第一版不提供批量删除，也不并行运行多个 MinerU/全文翻译重任务。

底层合法下载、解析、恢复和飞书读写能力仍保留，但由统一工作流调度，并只在失败处理或
高级菜单中出现。

## 用户流程

### 单篇入库

用户在对话中提供 DOI、题名、链接或基本题录并要求入库。系统：

1. 解析标识符和题录，优先用 DOI、PMID、arXiv ID 等稳定标识查重；无稳定标识时使用
   规范化题名、年份和作者组合查重，歧义时不合并。
2. 创建或复用 SQLite 记录。未指定主文件夹时 `folder_id` 为空，页面归入【待归类】。
3. 本地记录成功后立即返回；重复入库只补全已有记录，不创建副本。
4. 后台获取 Abstract，保留英文原文并生成逐段中文对照。找不到 Abstract 时标记
   【待补摘要】，不得根据题名编造内容。
5. 后台更新 XLSX 快照，并在飞书已启用时创建或更新对应记录。任一后台步骤失败都不
   撤销本地记录。

### 单篇精读

用户点击【开始精读】后，系统：

1. 复用已经通过哈希和 PDF 头校验的原件；否则先尝试合法自动获取。
2. 自动获取失败时把该文献转为【需要用户处理】，提供两个选项：使用用户已登录的机构
   浏览器，或挂接本地 PDF。插件不读取或保存账号、Cookie、验证码与 MFA 信息。
3. 把唯一 PDF 原件写入文献资产目录，记录来源、SHA-256、页数和获取时间。
4. 在持久后台任务中执行 MinerU 解析，保存 Markdown、图片、表格、页面与块级定位信息。
5. AI 按解析块逐段生成中文对照和重点标记；每个翻译块保留对应页码或 source block，
   中断后从未完成块继续。
6. 确定性渲染器生成一个可离线打开的 `reader.html`，随后更新 SQLite、XLSX 和飞书。
7. 页面上的【开始精读】替换为【阅读 HTML】。

### 精读 HTML 边界

- 正文逐段中英对照，图注中英对照；参考文献只保留英文。
- 图和表保持原文顺序与位置；不得把全文阅读替换成另一份长篇总结。
- 保留已经确认的阅读样式：左侧目录、重点高亮、隐藏重点和只看重点控件。
- 页面顶部可以有简短阅读提示，但九节式报告不再作为独立产物生成。
- HTML 与 PDF 的生成关系写入 manifest；PDF 哈希改变时，旧 HTML 标记为过期而不是静默
  视为最新版本。

## 文献导航页

### 页面结构

页面采用“可收起文件夹树 + 宽文献列表 + 临时详情抽屉”，不再常驻三栏。

左侧只显示：

- 【全部文献】；
- 【待归类】：`folder_id` 为空的文献，包括新入库未指定分类和 AI 无法可靠归类的文献；
- 用户创建的主文件夹。

【最近入库】是时间筛选而不是文件夹。标签是独立筛选维度，不伪装成文件夹。

顶部提供搜索、单篇添加、批量粘贴和状态筛选。搜索覆盖题名、作者、DOI 和标签。后台任务
只显示简洁汇总，例如【处理中 2｜排队 5】。

### 文献行与详情抽屉

每行显示多选框、题名、作者摘要、年份、主文件夹、少量标签、浅读/精读/飞书状态，并按
产物状态提供以下入口：

- 【浅读】：打开 Abstract 中英对照抽屉；
- 【开始精读】或【阅读 HTML】；
- 【PDF】；
- 【飞书】。

点击题名只打开轻量详情抽屉。抽屉包含完整题录、Abstract 中英对照、当前状态和失败原因，
以及 PDF、HTML、飞书和资产目录入口；不嵌入整篇 HTML，不展示 MinerU 参数。

更多菜单包含打开资产目录、整理文章图表和重试失败任务。只有失败状态才出现下载来源、
本地 PDF、重新解析等高级操作。

## 文件夹、标签和批量操作

- 每篇文献只有一个主文件夹，可以有多个标签；文件夹和标签都只存 SQLite，不移动或复制
  PDF、HTML 与解析资产。
- 列表多选后支持移动文件夹、添加/移除标签、加入精读队列、重试失败任务和重新同步飞书。
- 用户可在对话中要求 AI 批量归类。AI 默认只使用现有文件夹，以题名和 Abstract 为依据；
  低置信度文献保留在【待归类】，不得硬猜。
- AI 可以建议新文件夹，但只有用户明确要求创建时才可以创建。
- 每次批量归类记录受影响文献及变更前后的主文件夹/标签，支持撤销最近一次完整操作。
- 批量精读表示加入持久队列，不表示并行运行重任务。
- 一个内部子批次最多 100 篇；更大的用户请求自动拆成多个子批次，并由一个父任务汇总
  成功、重复、待处理和失败结果。
- 不支持批量机构浏览器下载；需要浏览器处理的文献逐篇进入【需要用户处理】。

## 数据所有权与本地资产

### SQLite

SQLite 是唯一事实来源，至少保存：稳定 `paper_id`、题录、英文/中文 Abstract、主文件夹、
标签、各阶段状态、任务 ID、错误原因、PDF/HTML/资产路径与哈希、飞书 `record_id`/直达链接、
创建/更新时间和批量归类操作记录。

每篇文献的 JSON manifest 是资产清单与可复现记录，不是第二份目录主库。目录结构逻辑上为：

```text
papers/<paper_id>/
├─ source.pdf
├─ reading/
│  └─ reader.html
├─ internal/
│  └─ parsed/
├─ exports/
│  ├─ figures/
│  └─ tables/
└─ manifest.json
```

实现迁移时优先兼容现有真实路径，不为了目录改名移动已经校验过的资产。

### 图表导出包

MinerU 原始解析资产长期保留在 `internal/parsed`，默认从主界面收起。用户按需调用【整理
文章图表】后生成派生导出包：

- 全部检测到的正文 Figure 按原编号和出现顺序命名为 `Fig_01.png`、`Fig_02.png` 等；
- 全部检测到的正文 Table 按原编号和出现顺序命名为 `Table_01.png`、`Table_02.png` 等；
- 表格图片优先保持原版式；只有 MinerU 已产生可靠结构化数据时才同时导出 `Table_01.csv`，
  不让 AI 猜测或重建缺失单元格；
- `captions.md` 和 `manifest.json` 记录编号、原页码、图注、源资产路径与 SHA；
- 不选择所谓关键图，不导出页眉、期刊 Logo 或其他非正文装饰图。

### XLSX

XLSX 是由 SQLite 生成的完整、只读、可重新生成的本地快照，不参与飞书同步，也不接受
用户修改回写。更新在后台以临时文件生成后原子替换；如果目标文件正被 Excel 占用，则记录
【待更新】并稍后重试，不阻塞入库或精读。

## 飞书同步

- 飞书直接从 SQLite 同步，不经过 XLSX。
- DSH 启动时只有在 `FEISHU_APP_ID`、`FEISHU_APP_SECRET` 和包含 `app_token`、`table_id`、
  `field_map` 的有效仓库外配置同时存在时才自动启用；缺少任一项只显示【飞书未配置】。
- 配置成功后，新建或发生系统字段变化的记录自动排队同步，不再逐篇预览和确认。首次启用
  不自动把全部历史库写入飞书；历史记录通过【重新同步所选项/全部待同步项】显式加入队列。
- 沿用已经确认的飞书表格列结构与映射。题录、Abstract、阅读状态、研究问题、方法、主要
  结果、创新、局限、PDF/HTML/图表资产路径等属于系统字段；精读完成后才补齐需要全文证据
  的字段。
- 个人理解程度、个人思考和其他用户拥有字段不进入更新 payload，用户在飞书中的修改不会
  被覆盖，也不回写 SQLite。
- SQLite 保存飞书 `record_id` 与可用直达链接；去重和更新优先使用稳定 record ID/paper ID，
  不依赖可能变化的题名。
- 【精读 HTML】列保存本地绝对路径文本。飞书网页不承担打开 `file://` 的职责；DSH 页面
  通过 `/sr/reader/<paper_id>` 提供真正的一键阅读。
- 飞书失败不改变本地完成状态。有限自动重试后标为【待同步】；单条失败不停止其他记录。
- App Secret 只从宿主环境变量继承，不写配置、SQLite、日志、job、XLSX 或响应。

## 后台架构与状态

确定性 worker 负责题录/数据库读写、PDF 获取与校验、MinerU、文件整理、HTML渲染、XLSX、
飞书和恢复；AI 只负责 Abstract 翻译、语义归类、全文翻译、重点识别和飞书精读字段生成。

所有任务持久化并幂等。轻量题录、Abstract 和同步任务可以有限并发；MinerU 与全文翻译默认
串行。重复点击同一阶段返回现有 job，不启动并行副本。用户界面只使用以下状态：

```text
正在入库 → 生成浅读 → 待精读 → 精读排队 → 获取 PDF
          → 解析全文 → 翻译与生成 → 精读完成
          ↘ 需要用户处理 / 处理失败
```

内部阶段、agent gate、心跳与重试次数保留在 job 状态中，但不作为普通用户的主状态名称。

失败处理遵守以下边界：

- Abstract 缺失不编造；
- 无效 PDF 不覆盖现有原件；
- MinerU 失败保留 PDF，可单独重试；
- 翻译按块提交并恢复；
- HTML 渲染失败保留解析与翻译产物；
- 飞书/XLSX 失败不阻塞本地库；
- 批量中单篇失败不终止其余文献。

## 迁移策略

1. 数据库 schema 变更前创建带时间戳的备份，并验证备份可打开。
2. 保留现有 PDF、MinerU 资产和精读 HTML，不重新下载或重新生成。
3. 旧九节式浅读作为历史文件保留并可查看；新流程只生成 Abstract 中英对照。
4. 旧的未分类记录统一表现为【待归类】；不创建名为“收件箱”或“待整理”的实体文件夹。
5. 停用并移除 Zotero 运行工具与 UI 文案；迁移期可以读取旧标识辅助查重，但不再写 Zotero。
6. 保留现有飞书表结构、映射和用户内容；迁移测试不得触发历史记录批量写入。
7. 每个迁移步骤具备读回校验；失败时恢复数据库备份，不删除已经存在的资产。

## 验收标准

1. 单篇 DOI 入库后目标在 3–5 秒内出现在【待归类】，后台补齐 Abstract、XLSX 和飞书。
2. 重复标识不产生重复记录；题名歧义不自动错误合并。
3. 一次 100 篇的内部批次包含重复、缺摘要和不完整元数据时，其余文献继续完成并有汇总。
4. AI 只用现有文件夹归类，低置信度项目留在【待归类】，一次批量归类可完整撤销。
5. 【开始精读】能完成 PDF、解析、翻译和 HTML；宿主退出后可以从已完成阶段恢复。
6. 自动下载失败只对相应文献展示机构浏览器/本地 PDF 选项。
7. PDF、HTML、飞书和资产目录入口均可用；HTML 与 PDF 哈希关系可追溯。
8. 图表导出包含 `Fig_*`、`Table_*`、图注和 manifest，结构化表格只在可靠时输出 CSV。
9. 飞书同步不覆盖个人字段，首次启用不自动写入全部历史库，失败不影响本地记录。
10. XLSX 被占用时入库和精读仍成功，文件释放后可以补写快照。
11. 普通桌面宽度下列表题名、年份、状态和快捷入口可读，详情抽屉不会常驻挤压列表。

## 测试策略

- **单元测试**：标识查重、文件夹/标签、状态转换、批量分块与撤销、系统/个人字段所有权、
  路径边界、manifest 和幂等 job。
- **离线集成测试**：使用虚构工科题录、固定 Abstract、本地测试 PDF、假 MinerU 和假飞书；
  不联网、不读取飞书凭证、不写真实数据。
- **引擎集成测试**：验证真实 SQLite、文件资产、后台 worker、宿主退出恢复、XLSX 锁定和
  逐块翻译恢复。
- **Profile 运行时测试**：在隔离 DSH Profile 中安装真实 tarball，检查插件启动、列表/详情、
  浅读/精读路由和关闭清理。
- **浏览器实测**：验证文件夹树、分页搜索、批量选择、Abstract 抽屉、快捷入口、队列状态和
  失败处理；不点击真实飞书写入或机构认证操作。
- **最终人工验收**：用一篇合法开放的非医学论文跑完完整链路；真实飞书只向专用测试记录
  写入一次并读回比对，完成后再允许正式自动同步。

## 实现顺序约束

先完成数据库/迁移与新的入库契约，再改浅读和精读编排，随后实现飞书/XLSX所有权，最后
重做导航页和批量操作。不得先改 UI 而让其依赖尚不存在的数据契约。每个阶段在隔离数据根和
Profile 中通过后，才允许更新用户当前 `web` Profile。
