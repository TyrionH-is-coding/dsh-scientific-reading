# 设置与状态页及高校认证闭环重构设计

## 1. 目标与边界

本轮只重构 DSH 文献模式中的【设置与状态】页和高校机构认证闭环。现有文献模式、文献页、SQLite 主库、Excel 派生视图、MinerU API、双语 HTML 和全文任务管线继续复用，不做无关重写。

面向普通用户的页面只展示用户能理解、能采取行动的信息。Python 路径、ScanSci 可执行文件、浏览器 Profile 路径、认证协议名和其他运行时参数不得出现在普通设置界面中。

PDF 获取始终使用合法来源。`legalOnly` 在产品层固定为 `true`，不提供 Sci-Hub、LibGen 或其他灰色来源入口。

## 2. 页面信息架构

【设置与状态】是文献模式下唯一面向普通用户的配置入口，按优先级展示四个区域：

1. **高校访问**：高校选择、认证状态、最近检测时间和当前唯一下一步操作；
2. **PDF 获取**：开放获取与高校访问是否可用，以及需要用户处理的下载状态；
3. **全文解析**：MinerU 是否可用、API Key 的保存/替换/删除入口；
4. **本地文献库**：SQLite、文献数量、Excel 同步状态和打开资产入口。

页面不显示独立的 CloakBrowser 卡片，不显示技术诊断字段。必要诊断保留在脱敏诊断报告和开发日志中。

## 3. 高校选择与认证流程

高校列表运行时取自当前安装的 ScanSci，不在插件中维护第二份静态名单，也不展示“已验证/未验证”标记。

用户流程固定为：

```text
搜索并选择高校
  -> 保存选择
  -> 开始认证
  -> 专用可见浏览器打开
  -> 用户完成账号、验证码、扫码或 MFA
  -> 插件检测会话
  -> 显示已连接及最近检测时间
```

系统依据 ScanSci 返回的学校配置自动选择认证实现。普通用户不选择 WebVPN、CARSI、EasyConnect 或 aTrust 等技术类型。

插件不读取账号、密码、验证码、MFA 或 Cookie 内容。ScanSci 在其专用本地数据目录中维护机构会话；插件只读取脱敏后的会话状态。

## 4. 状态模型

高校访问只使用以下用户态状态：

- `school_required`：尚未选择高校，操作是【选择高校】；
- `login_required`：已选择高校但没有可复用会话，操作是【开始认证】；
- `waiting_user`：认证浏览器已打开，等待用户完成登录；
- `checking`：正在检测会话；
- `connected`：最近一次真实检测确认会话有效；
- `reauth_required`：会话已过期，需要重新认证；
- `unreachable`：当前网络无法判断会话是否有效，不能误报为过期；
- `failed`：认证或检测失败，并显示可执行的重试动作。

页面中的“需要更新”只表示高校登录会话已过期、需要重新认证，不表示 ScanSci、插件或其他软件需要升级。

“已连接”只证明高校入口会话在最近检测时有效，不代表学校订阅了任意出版社或任意年份的文章。出版社明确拒绝授权时仍应返回“当前高校没有该文献权限”。

## 5. 接口与任务边界

保留现有环境状态快照和手动检测机制，扩展为清晰的高校认证接口：

- 查询高校：接受搜索文本，返回 ScanSci 的学校名称列表；
- 保存高校：只保存用户选择的学校身份，内部认证参数由系统解析；
- 开始认证：启动一次可见浏览器认证任务并立即返回 `waiting_user`，不得让页面请求阻塞到登录结束；
- 查询状态：返回认证任务和最近会话检测快照；
- 重新检测：由用户点击触发真实会话检测；
- 重新认证：仅在无会话或已失效时启动新的认证任务。

同一时刻只允许一个高校认证任务。重复点击必须复用当前任务或返回明确状态，不能弹出多个登录窗口。

## 6. 普通设置与兼容性

DSH 通用插件设置卡不再显示 `python`、`scansciExe`、`loginType`、`scansciPython`、`enginePython`、`legalOnly` 等字段。现有配置键可在内部保留兼容读取，但产品代码始终强制合法来源。

数据根和下载目录采用既有默认值。需要开发者诊断时通过脱敏报告处理，不把底层路径重新暴露给普通用户。

## 7. 错误与人工接管

认证页面出现验证码、二维码、短信、MFA、Cloudflare 或出版社人机验证时，自动化立即停止并等待用户操作。用户完成后只从同一任务继续一次，不循环重试。

网络不可达、会话过期、学校无订阅权限和出版社人机验证必须是四种不同状态，不能统一显示为“下载失败”。

认证失败不得影响 SQLite、已有 PDF、MinerU 结果、HTML、Excel 或其他文献任务。

## 8. 验收标准

自动化验收至少覆盖：

1. 高校搜索和选择只使用 ScanSci 返回的数据；
2. 普通页面和 DSH 插件设置中不存在技术路径、认证类型和灰色来源开关；
3. 首次认证、等待用户、已连接、过期、不可达和失败状态映射正确；
4. 重复点击认证不会启动多个浏览器任务；
5. DSH 重启后可读取同一专用会话状态；
6. 过期会话明确显示【重新认证】，网络不可达不误判为过期；
7. 全文管线仍强制 `legal_only`；
8. 现有文献页、MinerU API、SQLite、Excel 和 HTML 合同测试继续通过。

真实分层验收至少包括：选择一个实际高校、完成一次可见浏览器认证、确认状态为已连接、重启 DSH 后重新检测、模拟或等待会话失效后完成重新认证。需要验证码或 MFA 的步骤必须由用户亲自完成。
