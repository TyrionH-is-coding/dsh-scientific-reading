# 双项目文献工作台工程规划

日期：2026-09-05。状态：用户已明确双项目产品方向；本文整理工程边界和后续验收，不代表功能已实现。

## 1. 已确定的产品分工

最终形成两个可独立安装、版本化发布的项目：

| 项目 | 用户入口 | 全文来源 | 核心责任 |
| --- | --- | --- | --- |
| A：DSH Scientific Reading 原生插件 | 用户自己的 DSH | 自动 OA 获取、补入本地 PDF | 文献库、摘要、解析、翻译、Reader、图表与 Excel |
| B：Codex 文献工作台 | Codex 对话和内置浏览器中的专用 DSH | A 的 OA 能力，加上 Codex 执行的授权获取，失败后手动补 PDF | 总管理、隔离运行环境、分类管理员调度、结果验收 |

A 使用现有 dsh-scientific-reading 仓库。B 另建仓库，暂用 codex-scientific-reading 作为规划名称，尚未创建仓库。

B 固定依赖 A 的发布包，不复制 A 的源码，不另写一套数据库、MinerU 或 Reader。对 A 的修复回到 A 发布；B 更新经过验证的依赖版本。

本轮新方向取代旧方案中“由 DSH 文献插件负责高校认证下载”的职责安排。此前独立 DSH、SQLite、长期资产保留等约束继续适用。

## 2. 项目 A：收敛为原生文献插件

保留：

- DOI、PMID、题名等输入的查重、题录补全、摘要与双语浅读。
- 有开放来源证据、可匿名获取的 OA 正文，包括合法开放仓储版本。
- 通过文件选择、上传或受控文件导入接收已有 PDF。
- PDF 文件头、可解析性、文献身份与 SHA 校验。
- 现有持久任务、MinerU、翻译、Reader、图表导出和 Excel 派生。
- DSH 原生模型配置；插件本身不要求 Codex 账号。

从本插件的正式下载路径退出：

- 学校配置、CARSI、WebVPN、机构 Chrome 登录与会话接力。
- 导入 Cookie、读取浏览器 Profile、为机构访问复制凭据。
- 因下载受阻而调用增强浏览器或逐层尝试机构登录。

OA 获取受限或来源不明确时，保留题录和摘要，进入“待补 PDF”；不阻断其他文献。PDF 补入后继续原记录，不要求用户重新录入。

上述来源限制在下载器和工具实现中执行，不依赖模型遵守提示词。模型不能通过参数把 OA 模式切成机构模式。限制对象是本插件的文献获取能力，不修改用户宿主中其他插件的行为。

上传入口统一提供文件导入合同。用户手动上传，以及 B 将已取得的本地文件交给 A，走相同校验和入库过程；外部下载器不直接写 SQLite 或正式 generation。

## 3. 项目 B：独立安装与运行

推荐“专用 DSH 运行目录 + 专用 DSH_HOME”。只增加 profile 名称不足以满足隔离目标；维护一套 DSH 核心分支则增加不必要的维护成本。

源码依据：当前 rc.7 会在 profile 补丁之后加载 DSH_HOME 下的 home 级补丁，并维护 profiles/node_modules 依赖查找目录。因此 B 不能复用用户默认的 DSH home 或默认安装目录。

隔离合同：

| 对象 | B 的规则 |
| --- | --- |
| DSH 与插件依赖 | 使用项目自有安装目录和锁定版本；启动绝对路径，不调用 PATH 中任意 dsh 或在线 latest |
| 配置与 preset | 为子进程显式指定专用 DSH_HOME；不继承用户默认 home 级插件、补丁、preset 或模型设置 |
| Node、Python | 使用项目受控运行版本和专用 Python 环境，不升级用户全局环境 |
| 会话与日志 | 全部位于 B 的状态目录；与用户原 DSH 会话分离 |
| 文献资产 | B 默认创建自己的数据根；已有文献库须经显式导入或迁移，不自动挂载同一活动数据库 |
| 端口和进程 | 独立本机端口、实例身份和进程记录；冲突时选择可用端口，不关闭用户现有 DSH |
| 浏览器连接 | Codex 打开本次实例返回的地址；连接时核对实例身份，不只认固定的 localhost 端口 |
| 升级和卸载 | 按版本替换运行包，保留文献资产；只停止本实例，不修改用户原 DSH |

第一版以 Windows 单用户本地安装为基线。应用运行目录、凭据目录与用户文献数据分开；不改变 HOME、用户级 DSH_HOME 或全局模型凭据。

DSH 可以作为独立进程继续处理已提交的任务。用户关闭 Codex 对话不等于删除任务；再次进入时读取持久状态并恢复管理。

“已安装其他版本 DSH”“已有其他插件”“已有 3080 服务”均为正式并存验收场景。

## 4. 两级管理员与会话

一个 B 实例包含一套全局文献库，以及多个分类会话；不为每个分类启动新的 DSH 实例或复制数据库。

| 角色 | 工作范围 |
| --- | --- |
| Codex 总管理员 | 全库检索、建立分类、跨分类调整、批次调度、授权获取、汇总与验收 |
| DSH 分类管理员 | 本分类的题录、摘要、阅读任务、笔记和进度；向总管理员返回结构化结果 |
| 单篇整理会话 | 复用现有 Review 能力，继承分类范围，围绕指定论文的证据和确认结论工作 |

每个分类使用稳定 folder_id；分类会话显式绑定 folder_id 与 DSH session_id。标题只是显示名称，重命名对话或分类不改变绑定。每个分类默认复用一个主管会话，可续接和归档。

分类作用域在 B 使用的受限文献模式及工具层执行：

- 查询自动注入绑定的分类范围；修改核对目标论文所属分类。
- 单篇子会话继承范围，不能因另起对话获得全库权限。
- 不向分类管理员暴露可绕过文献服务的任意 SQL、全局写库或不受限维护工具。
- 跨分类移动、合并等操作交给总管理员或用户的明确管理操作。
- 分类被归档或论文被移动后，旧任务写回须重新校验归属和输入版本。

现有 library_tools 的 folder 参数可选，尚不能视为分类隔离已实现；需要补会话绑定和服务端范围校验。

沿用一篇论文一个稳定 paper_id 和现有分类、标签语义。跨分类检索不复制 PDF；不在本轮擅自改成一篇论文多主分类。

## 5. Codex Skill 与任务交接

Skill 负责总管理流程与决策规则；任务事实仍保存在 A 的 SQLite 和持久任务中。更换 Codex 对话后，从实例、分类绑定和任务记录恢复，不依赖聊天记忆。

内置浏览器保留 DSH 对话、文献页和 Reader 的可见体验。机器调度优先复用可验证的本地接口；缺少的接口只补创建或恢复分类会话、提交任务、读取状态、导入文件等必要能力。

交接至少携带：实例身份、task_id、folder_id、paper_id 或目标集合、请求动作和结果资产标识。

- 重复提交同一操作应复用有效任务。
- 两个管理员同时处理同一论文时，通过已有任务身份和版本校验避免重复工作及覆盖。
- DSH 输出“完成”只是会话消息；Codex 还要读取任务结果和实际资产。
- 分类管理员遇到需要人工操作的状态，只报告该阻塞，不自动反复向总管派生相同任务。

授权文献获取由 Codex 侧负责：使用现有 ScanSci PDF、合法来源和本人授权的常用 Chrome；机构认证继续由用户本人完成。内置浏览器中的 DSH 不需要继承 Chrome 登录信息。

有限尝试后仍失败，保持“待补 PDF”。本人提供文件后，调用 A 的统一导入接口续接。B 内置的 A 仍只自动抓取 OA，不因运行在 B 中而开启隐藏的机构下载模式。

## 6. 原生模型配置与 Codex 订阅接入

两项目均保留 DSH 原生模型设置。A 不捆绑或维护 Codex OAuth；用户自己的 DSH 已配置什么兼容提供方，就使用宿主能力。

B 负责将选定的 Codex 订阅接入插件作为受控依赖打包，提供登录、状态、模型选择和可用时的额度显示。无需为此重新发明 OAuth 协议。

本机已有 D:\Vibe Coding\dsh\dsh-codex，包版本为 0.1.0。已读 README 和源码：它复用官方 Codex 已有登录态并注册 DSH provider，属于订阅桥接；并不自行提供完整 OAuth 登录流程。该目录没有 Git 仓库信息，尚不能确认其对应的 GitHub 上游。此前生成连接的 WebSocket 代理问题继续列为真实兼容案例，不能以“本机已安装”替代验收。

已找到两类可复用社区候选，当前仅核对公开文档与包信息，未安装或实测：

| 候选 | 作者文档描述的接入方式 | 本项目需要验证的重点 |
| --- | --- | --- |
| birat-chapagain/dsh-codex-oauth | DSH provider 插件，提供 OAuth 人工登录命令，凭据存储路径跟随 DSH_HOME，可配置传输方式 | 锁定版本的 DSH 兼容、Windows 凭据保护、刷新、代理与工具循环 |
| DGPisces/dsh-openai-oauth | 对接本地官方 Codex app-server，由其管理登录与刷新 | 专用运行与凭据目录、工具循环兼容；其默认安装器会处理多个 profile，不能直接用于我们的宿主隔离安装 |

优先从现有实现中选择通过隔离和功能验收的一个，避免同时注册冲突的 Codex provider。默认安装脚本、全局路径和自动清理旧包逻辑须审查后再定向集成；不是将上游一键安装命令照搬到用户环境。

若使用官方 app-server 路线，官方文档已提供登录、退出和额度读取接口，但 App Server 和动态工具接入仍有实验性说明，应作为兼容性约束纳入版本锁定和验收。不能只证明 OAuth 成功，就宣布 DSH 的模型调用已兼容。

本产品不复制外层 Codex 的凭据到文献库；凭据由所选登录组件在独立位置管理，模型工具和日志不读取或展示令牌。登录失败或额度不足不影响 DSH 其他已配置模型的存在，不静默切换计费方式。

外层 Codex 总管理员与 DSH 中通过同一账号使用的 Codex 模型，不因两个项目或多个分类而获得独立订阅额度。额度页读取服务返回的窗口和状态，缺失信息显示不可用，不能显示成剩余零或无限。

## 7. 单一数据合同与复用

- 每个安装实例一套 SQLite 事实源。A 独立安装与 B 默认不同时打开同一活动文献库。
- B 的所有分类管理员共享 B 的这套库，通过权限范围管理；聊天记录不是第二套文献数据库。
- Excel、Reader 和元数据文件继续作为派生视图或资产索引，个人笔记沿用既有受限回写规则。
- 导入的 PDF 记录来源类型和文件身份；已有论文附件不因换产品或换分类而重新计算成网络下载成功。
- 迁移文献使用可校验的导入或备份恢复流程，不通过复制整套运行目录和凭据完成。

#### 0.2 自定义保留的设计方向

届时建议将文献设置分为“服务与存储”“Excel 展示”“HTML 模板”三个区域。模型与 OAuth 仍使用 DSH 原生设置；任务进度仍放在文献页。配置和模板能力由 A 提供，B 复用，并可通过 Codex 对话协助生成方案和预览。

0.2 的 Excel 自定义分两层安排：

- 先开放现有字段的显示、隐藏、顺序、显示名称、列宽与换行，支持保存和恢复展示方案。隐藏一个字段只改变展示，不删除 SQLite 中的值。
- 新增“实验模型”“样本量”等课题字段属于独立的数据能力：需要定义字段身份、类型、值及来源。先支持人工填写；如要求 AI 从全文整理，另提交提取任务并保留证据位置，不把新增表头视为已经获得数据。

回写依据稳定的字段 ID 和 paper_id，不依赖用户看到的列名或列序。当前 xlsx_snapshot.py 固定表头，并要求三个用户字段都存在，必须同步调整导出与导入合同；仅添加界面勾选框不够。切换方案前保留尚未回写的笔记，隐藏或未导出的字段不能按空值覆盖主库。系统字段继续只读；以后新增的用户字段需显式纳入允许回写的范围。

HTML 自定义同样提供两个入口：普通用户选择模板并调整字体、颜色、宽度和双语布局；进阶用户导入符合模板约定的 HTML/CSS，或让 Codex 根据示例制作模板。0.2 的初始模板组合文献元信息、正文、译文、图表、导读等稳定组件，保留原文定位与交互所需的身份和锚点，不要求用户修改引擎代码。

模板负责排版，正文、译文、图表和结论由已有数据生成。仅更换样式和布局时只重新渲染，不重新调用 MinerU 或翻译模型；若用户要求新增导读或提取信息，则作为内容任务单独处理。精读模板须保留完整内容及证据入口；仅展示摘要的模板应明确标为摘要视图。

模板支持导入、预览、应用和恢复默认。导入按 HTML/CSS 与指定组件接口验证，不直接在 DSH 宿主页执行任意模板脚本。模板版本与内容版本分开记录，渲染缓存和产物清单包含模板身份；纯样式变化保持文献与正文块身份，并验证已有个人标记的续用，不能把“HTML 能打开”当成完整验收。

建议先支持全库默认方案，再按需要允许分类选择独立方案；分类管理员只能调整其所属分类，总管理员可设置全库默认。方案切换明确作用范围，旧产物保留到新版本成功生成，不在修改设置时批量重跑全文任务。

本项仅进入 A 的 0.2 待办，B 无需另写模板引擎。建议先完成已有 Excel 字段配置及模板加载、预览，再扩展自定义研究字段。具体交互和阶段顺序在实施前细化，不纳入下方 0.1 收口阶段。

0.2 对应验收：更换列名和列序后仍能准确回写笔记；隐藏用户字段不丢数据；切换模板不产生解析或翻译调用；正文、图表、引用定位完整；个人标记可续用；无效方案保持现有工作簿和 Reader；默认方案与已有数据兼容。

### 7.2 0.2 文献雷达（待做）

将既有文献发现与推荐规划并入本项：Agent 根据用户目标、已有文献和种子论文整理方向；需要探索时提出有文献依据的子方向，用户确认或修正后形成可复用配置，再自动检索、去重、筛选并解释推荐。方向配置始终可修改，后续扫描不重复询问已确定的方向。

雷达核心和候选数据由 A 提供，B 复用。A 用户通过 DSH 对话使用；B 中 Codex 总管理员统筹多个方向，DSH 分类管理员处理对应分类的候选，沿用既有作用域边界。

方向配置保存研究问题、关键词与同义词、种子文献、纳入与排除范围、关注的研究类型。扫描支持按需执行，未来可按用户设定频率增量运行；这只是版本规划，本次不启动实际后台检索或定时任务。

推荐分别解释相关性、方法与证据、当前研究价值和时效性；期刊影响因子、引用数不能代替对论文的判断。经典研究、新进展及相关的阴性或相反结论均可进入候选。摘要初筛明确其信息范围，不显示为全文质量评价；预印本、撤稿和更正等状态按可核实来源标注，未知项不补造。

候选保留稳定标识、发现来源、检索时间与查询、推荐理由、判断依据及全文可获取状态，并与文献库、历史候选去重。用户筛选反馈用于后续过滤；无新增相关条目时保持安静。候选列表与正式文献库分开，用户选择纳入后再衔接既有 PDF、解析和精读流程。

检索和推荐可以覆盖非 OA 文献，全文获取继续遵守 A/B 分工。雷达不因候选属于非 OA 就排除其研究价值，也不改变 A 只自动获取 OA 的产品边界。

具体提供方和界面在 0.2 实施前细化；验收须覆盖方向复用、去重、来源可追溯及相关/无关/相反结论样本，不能把接口调用成功当成优质推荐。详细流程同步维护在[发布路线](../../roadmap.md)。

现有项目与 Skill 的[复用调研](../../../outputs/literature-radar-research-2026-09-05/调研报告.md)已完成。建议裁剪 paperradar、医学雷达及方向/证据判断 Skill 的合适部分，不引入平行数据库、模型配置或推送系统；无 DOI 去重、启发式质量分、候选留痕和增量日期语义需要按本项目合同处理。已做公开元数据接口和有限纯函数验证，尚未安装候选依赖或完成 Agent 质量横评，具体选型仍以 0.2 实施验收为准。

## 8. 分阶段交付与验收

| 阶段 | 主要工作 | 必须通过的验收 |
| --- | --- | --- |
| 1：A 0.1 收口 | 固化 OA 获取和本地 PDF 导入；退出机构下载入口及调用；精简设置，沿用固定 Excel 与默认 Reader | OA 成功；订阅或挑战路径不会自动升级到机构登录；错误文件拒收；补 PDF 续接；旧数据与用户笔记保留；默认阅读链可用 |
| 2：B 隔离包装 | 新建独立项目，固定依赖 A、DSH 与运行环境；安装 Skill 和专用启动入口 | 无全局 DSH 也能运行；与已有 DSH 同时运行；其配置和插件不被更改；端口冲突处理；重复启动不产生重复实例 |
| 3：两级管理 | 分类与会话绑定、作用域控制、总管交接和持久状态读取 | 分类越界操作被拒绝；会话重命名不丢绑定；重复任务不重复执行；换 Codex 对话及重启后能恢复 |
| 4：订阅接入 | 对比现有组件后固定一个版本，定向安装并接入原生模型配置 | 登录、刷新、退出；实时模型及推理能力；多轮工具调用；取消与续聊；代理；额度不足；不污染外层 Codex 或用户原 DSH |
| 5：发布组合验收 | 为 A、B 分别生成发布包和支持矩阵 | 干净安装、升级、卸载保留数据；来源和包 SHA 可追溯；非 OA 获取失败后手动补文件能续接；全流程资产回读 |

B 的隔离骨架准备可以与 A 收口独立进行，但正式打包只能引用已通过验收的 A 版本。OAuth 候选核对可以前置，实际接入验收需要使用 B 的隔离实例。

以上是两个项目的依赖和交付顺序，不要求同步发布。A 的 0.1 达到自身发布条件即可先发布，B 的独立包装不阻塞 A；0.2 自定义与文献雷达不进入任一项目 0.1 的工期或验收门槛。当前版本安排同步记录于[发布路线](../../roadmap.md)和[开发待办](../../coding-backlog.md)。

每次 B 发布固定兼容组合：B 版本、A 版本、DSH 版本、OAuth 插件版本，以及 Node、Python、必要时 Codex CLI 的版本或包校验信息。升级先验证这组组合，不在用户启动时追踪 latest。

当前仓库存在大量已有未提交改动；本次版本收口只更新工程规划、发布路线和开发待办，功能实现与运行环境验收另行记录。
