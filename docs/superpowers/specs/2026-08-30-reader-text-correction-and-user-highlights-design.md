# Reader 文本校正与个人荧光笔设计

## 决策摘要

在 MinerU 解析与 `reader.html` 渲染之间增加可审计的英文文本校正能力，并在阅读页加入仅保存在本机的个人荧光笔。

文本校正不新增独立的整篇 LLM 调用。确定性规则先处理可安全判定的排版错误；现有全文翻译批次同时返回校正后的英文、中文翻译和 AI 重点。只有通过保守校验的高置信度校正才直接生效。MinerU 原始文本始终保留，校正以独立清单记录，不覆盖解析资产。

个人荧光笔允许用户在单个正文段落内选择文字并添加黄色、绿色或粉色标注。标注按论文保存在当前 DSH 浏览器的 `localStorage`，关闭后重新打开仍可恢复；不做服务端同步、跨机器迁移、导出、笔记或跨 HTML 版本迁移。

## 目标与非目标

### 目标

1. 修复 `modi<sup>fi</sup>ed`、`f<sup>i</sup>rmly` 等 MinerU 将单词片段误判为上下标的问题。
2. 修复有充分上下文证据的缺失空格、错误断词和标签裸露问题。
3. 让正文英文、中文翻译和后续重点判断使用同一份已校正英文。
4. 保留原始文本、修改内容、修改原因、置信度和校验结果，保证可追溯。
5. 让用户在当前机器上快速添加、查看、跳转和删除个人荧光笔。
6. 不显著增加单篇论文的墙钟时间。

### 非目标

- 不润色作者文风，不改写句式，不统一英美拼写。
- 不自动修正文献中的事实、数字、单位、统计结果或科学结论。
- 不让 LLM 改写公式、引用编号、DOI、URL、基因名或专业缩写。
- 不提供用户笔记、书签、云同步、飞书同步或标注导出。
- 不提供 HTML 重新生成入口，也不实现跨版本标注迁移。
- 不改变 AI 重点的 `result` / `method` 语义。

## 现状与问题来源

当前解析文本保存在 `SourceBlock.text`，全文翻译合同要求 `source_text` 与解析文本严格一致。reader 构建器把文本中的安全字面 `<sup>` / `<sub>` 转成真实标签。这对作者脚注和正确上下标有效，但也会忠实放大 MinerU 的结构误判：

```text
modi<sup>fi</sup>ed  ->  modiᶠⁱed
f<sup>i</sup>rmly    ->  fⁱrmly
```

因此问题不是单纯 CSS 错位，而是解析语义进入渲染层前缺少校正。另一方面，当前阅读器已有 AI 重点、阅读模式、翻译折叠和 `localStorage` 阅读状态，但没有独立的用户文本标注。

## 文本校正架构

### 1. 原始解析资产保持不可变

`source_map.json`、MinerU 原始文件和 `SourceBlock.text` 继续表示解析器原始输出。校正层不得原地覆盖这些文件。

后续阶段使用“有效英文文本”概念：

```text
effective_text = accepted corrected_text_en or SourceBlock.text
```

校正结果单独写入当前 generation 的精读资产目录，并纳入 reader revision 与 manifest SHA。

### 2. 确定性预处理

在提交翻译批次前运行小而保守的规则集：

- 当字母型 `<sup>` / `<sub>` 位于同一个英文单词内部时，去掉标签并无空格拼接；
- 将字面安全标签规范化，但不执行任意 HTML；
- 合并明确的行末连字符断词，仅在前后均为字母且词典或上下文验证通过时生效；
- 识别可疑的字母粘连、缺失空格和异常单字符上下标，生成风险标记；
- 作者单位脚注中的数字、`*`、`†`、`‡` 等合法上下标保持不变；
- 数学区域、公式块、DOI、URL 和引用区域不做通用空格规则。

规则修复必须生成与 LLM 校正相同格式的编辑记录，不能成为无账本的隐式改写。

### 3. 与现有翻译批次合并

不新增“整篇校文”模型阶段。现有逐批翻译请求增加以下职责：

- 检查每个非参考文献正文块是否存在 OCR/排版错误；
- 返回 `corrected_text_en`，无修改时必须与输入完全一致；
- 返回中文翻译，翻译依据 `corrected_text_en`；
- 返回有限的结构化编辑列表，而不是自由文本解释；
- 保持现有 `highlight` 输出。

新合同采用向后兼容升级。每一行至少包含：

```json
{
  "block_id": "p0002-m0014",
  "source_text": "modi<sup>fi</sup>ed by",
  "corrected_text_en": "modified by",
  "translation_zh": "经……修饰",
  "highlight": "none",
  "correction": {
    "status": "corrected",
    "confidence": "high",
    "edits": [
      {
        "before": "modi<sup>fi</sup>ed",
        "after": "modified",
        "reason": "alphabetic_fragment_misclassified_as_superscript"
      }
    ]
  }
}
```

旧合同或旧 generation 没有 `corrected_text_en` 时，以 `source_text` 作为有效英文文本，保持只读兼容。

### 4. 自动接受门

用户已确认高置信度校正直接生效。系统仍须在模型输出后执行确定性校验：

- `block_id`、批次顺序和原始 `source_text` 必须精确匹配；
- 所有数字、百分号、单位、引用编号、DOI、URL 和公式 token 必须保持；
- 不允许整段删除、增加新句或大幅改变长度；
- 编辑必须能按顺序在原文中定位，并能重放得到 `corrected_text_en`；
- 仅接受允许的排版/OCR 原因枚举；
- 仅 `high` 置信度且全部校验通过的修改直接生效。

校验失败、低置信度或涉及受保护 token 时，保留原始文本，写入 warning，不阻塞整篇 reader 生成。warning 不在正文常驻展示，只进入校正清单和 reader manifest 的计数摘要。

### 5. 校正清单

新增 `text-corrections-v1` 资产，记录：

- parser/source SHA；
- 校正合同与模型/规则版本；
- 每个修改块的原文、有效文本、编辑列表和接受状态；
- 被拒绝或跳过的可疑块及原因；
- 总块数、修改数、拒绝数和 warning 数。

reader revision 必须包含校正清单 SHA。这样相同输入可复现相同 HTML，解析原文也始终可审计。

## Reader 渲染行为

- 英文正文显示 `effective_text`。
- 中文翻译基于同一 `effective_text`。
- AI 重点继续作用于原 `block_id`，不因文本校正失去定位。
- HTML 不常驻显示“已由 AI 修正”徽章，避免打断阅读。
- 解析原文与修改账本保存在资产中，不把审计界面塞进当前 reader。
- `<sup>` / `<sub>` 只在通过安全语义规则后渲染；单词内部的字母片段不会再成为角标。

## 个人荧光笔

### 交互

用户在一个正文块内选择文字后，选区附近出现紧凑工具条：

- 黄色；
- 绿色；
- 粉色；
- 取消。

点击现有个人标注可更换颜色或删除。点击页面空白处关闭工具条。跨段落、跨图表、空白选区和仅包含控件的选区不创建标注。

### 与 AI 重点的区分

AI 重点继续使用浅色整句/整段底纹与页边圆点。个人荧光笔使用更鲜明的局部文本底纹，并带独立的 `data-user-highlight` 语义。二者可以叠加，不能互相覆盖或删除。悬停个人标注时显示简短的“个人标注”提示。

### 保存合同

标注只保存到当前浏览器：

```text
localStorage key: sr-reader-user-highlights:<paper_id>
```

每条记录保存：

```json
{
  "id": "本地唯一ID",
  "block_id": "p0002-m0014",
  "language": "en",
  "start": 14,
  "end": 36,
  "quote": "B cell populations",
  "color": "yellow",
  "created_at": "ISO-8601"
}
```

偏移量以所属正文块的纯文本为基准，不使用屏幕坐标。第一版只保证同一 HTML、同一机器、同一浏览器存储中的恢复，不承诺模板或正文变化后的迁移。

### 我的标注

工具栏增加一个低干扰的“标注 N”入口。打开后显示当前论文的标注列表，包含颜色、短引文和所属章节；点击列表项跳转并短暂强调对应文本。第一版不提供搜索、笔记、导出和排序配置。

## 数据流

```text
MinerU SourceBlock.text（不可变）
  -> 确定性规则预处理与风险标记
  -> 现有翻译批次：英文校正 + 中文翻译 + AI重点
  -> 自动接受门
  -> text-corrections-v1 + translations
  -> effective_text
  -> reader.html

reader.html 文本选择
  -> 单段落选区校验
  -> 本机 localStorage
  -> DOM 标注恢复 + 我的标注列表
```

## 错误处理

- LLM 未返回校正字段：该块回退到原始文本；翻译合同仍按兼容规则处理。
- LLM 校正不通过保护 token 校验：拒绝校正、保留原文、记录 warning。
- 某块校正失败：不阻塞其他块和 reader 发布。
- `localStorage` 不可用或配额异常：当前页面标注仍可使用，但显示一次非阻塞提示“关闭页面后可能无法保留”。
- 标注记录损坏：忽略无效记录，保留其他有效记录，不阻塞 reader。
- 标注偏移越界或引文不匹配：忽略该条并从列表移除，不尝试模糊迁移。

## 性能约束

- 不增加第二次整篇 LLM 调用。
- 确定性预处理为单次线性扫描。
- 只为实际发生的修改写详细编辑记录。
- 标注恢复按正文块分组，避免每次滚动扫描全文。
- 页面加载时一次恢复；滚动过程不重复重建标注。

## 测试与验收

### 文本校正

1. `modi<sup>fi</sup>ed` 渲染为 `modified`，`f<sup>i</sup>rmly` 渲染为 `firmly`。
2. 作者脚注 `Name<sup>*</sup>` 和合法数字上下标保持正确。
3. 缺失空格的高置信度测试样本被修复，原始文本仍存在校正清单。
4. 修改数字、公式、引用、DOI、URL 的模型输出被拒绝。
5. 低置信度修改不生效，但不阻塞 HTML。
6. 中文翻译声明的源文本与有效英文完全一致。
7. 旧翻译合同和无校正清单的旧 generation 仍可读取。
8. reader manifest 和 revision 纳入校正清单 SHA。

### 个人荧光笔

1. 在单个英文段落内选择文本可创建三种颜色标注。
2. 点击现有标注可以换色和删除。
3. 刷新或重新打开同一 reader 后标注恢复。
4. AI 重点开关不隐藏或删除个人标注。
5. “我的标注”数量、列表和跳转正确。
6. 跨段落选择、损坏记录和不可用存储安全降级。
7. 桌面和移动端工具条不遮挡主要正文，没有横向溢出。

### 实机验收

- 使用至少三篇非敏感、版式不同的论文验证校文：普通双栏论文、含大量公式论文、含作者脚注和上下标论文。
- 对截图所示的 `fi` 误角标建立固定回归样本。
- 在 DSH 实际阅读路由完成选择、着色、刷新恢复、列表跳转、换色和删除。
- 记录处理前后每篇的额外墙钟时间，确认没有新增独立 LLM 往返。

## 实施边界

- 当前工作树存在其他在途改动；实施必须在隔离 worktree 中进行并只合并本设计相关文件。
- 不顺带实现用户笔记、书签、云同步、标注导出、全文重生成入口或新的下载能力。
- 任何校正不得覆盖 MinerU 原始资产。
